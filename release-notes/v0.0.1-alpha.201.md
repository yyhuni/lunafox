# v0.0.1-alpha.201

## English

### Fixed

- Fixed engine scans failing with "The Agent could not pull the Engine Runtime Image" when the image was already present on the local Docker daemon but the registry channel was unreachable; the Agent now resolves digest-qualified engine images from the local daemon first and only falls back to a remote pull on a miss, with one bounded retry round for transient network-shaped failures and a lifecycle log event recording whether each task used a local or remote image.

### Documentation

- Documented the engine runtime image resolution policy - local digest-first resolution, remote candidate fallback, and the bounded retry round - as a maintained specification.

Full Changelog: https://github.com/yyhuni/lunafox/compare/v0.0.1-alpha.200...v0.0.1-alpha.201

## 简体中文

### 修复

- 修复了镜像已存在于本地 Docker daemon、但 registry 通道不可达时，引擎扫描报 The Agent could not pull the Engine Runtime Image 并连带取消整场扫描的问题；Agent 现在优先从本地 daemon 解析 digest 匹配的引擎镜像，仅在本地未命中时回落远程拉取，对瞬时网络类失败增加一轮有界重试，并新增生命周期日志事件记录每次任务使用的是本地还是远程镜像。

### 文档

- 将引擎运行时镜像解析策略（本地 digest 优先、远程候选兜底、一轮有界重试）沉淀为维护规范。

完整变更记录：https://github.com/yyhuni/lunafox/compare/v0.0.1-alpha.200...v0.0.1-alpha.201
